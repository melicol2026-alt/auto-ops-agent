# 04 执行层与风控设计

## 一、核心立场

用户底线通常只有一条：**别封号**。
底线之上（发布、评论、点赞、收藏、养号）全部自动化。
封号风险用**频次、时段、拟人化、熔断**去压，**不是靠"让用户手动发"来规避**。

把执行动作推回用户 = 降低用户效率 = 失职。

## 二、七道防封闸

| # | 闸 | 做法 |
|---|---|---|
| 1 | **频次硬限** | 写进 `config.py`，脚本自身越不过。参考值：发布 1 条/天、评论 3 条/天、点赞 8 次/天、收藏 3 次/天、**关注 0**（批量关注是封号重灾区） |
| 2 | **真实浏览器 + 持久化 profile** | 用 `launch_persistent_context` + 系统已装的 Chrome/Edge，指纹比 Playwright 自带 Chromium 真实。脚本从头到尾**不读写 Cookie、不碰凭据文件** |
| 3 | **随机间隔 + 作息时段** | 动作间隔 8–25 分钟随机；只在 9–11 / 14–16 / 20–22 活动，不在凌晨批量操作 |
| 4 | **先阅读再操作** | 进笔记后先分段滚动（每段随机停顿 1.2–3.5s）再点赞/评论，模拟真人阅读 |
| 5 | **只在同赛道内容下活动** | 互动目标是同赛道关键词的笔记，保证人群相关，也避免行为画像漂移 |
| 6 | **风控词熔断** | 页面出现"验证""异常""操作频繁""请稍后再试"等，立即中止当日全部任务并记日志 |
| 7 | **高危动作根本不排期** | 批量关注、私信、站外导流、刷量——**不写代码**，没有代码就不会被执行 |

## 三、登录态：一次扫码，永久复用

```python
ctx = pw.chromium.launch_persistent_context(
    user_data_dir=PROFILE_DIR,      # 固定目录，登录态落在本地
    channel="msedge",                # 或 "chrome"，用系统真实浏览器
    args=["--disable-blink-features=AutomationControlled"],
    locale="zh-CN", timezone_id="Asia/Shanghai",
)
ctx.add_init_script("Object.defineProperty(navigator,'webdriver',{get:()=>undefined});")
```

**技巧：与采集工具共用同一个 profile 目录。**
若同时用 MediaCrawler 采集（其 profile 为 `<repo>/browser_data/xhs_user_data_dir`），
把发布侧的 `PROFILE_DIR` 直接指向它，并关闭 MediaCrawler 的 CDP 模式，
即可实现**全系统只扫一次码**。

### 登录判据陷阱（必踩）
**不能拿"URL 里包含目标路径"当登录判据。**
目标 URL 本身就是 `/publish/publish`，这个条件恒真 —— 未登录会话会被误判为已登录，
脚本随即以游客身份去点搜索、点赞，白白累积风控却什么都没干成。

正确判据，三条同时满足：
```python
1. URL 不含 /login、不含 redirectReason
2. 页面正文不含登录墙特征词（"短信登录""手机号登录""扫码""登录后查看"）
3. 页面真的出现发布入口（locator("text=发布笔记").count() > 0）
```

### 无人值守模式
定时自动化必须用 `wait_login=False`：检测不到登录态立刻报错退出，
**绝不以游客身份继续操作**。

## 四、自动发布

- **多候选选择器**：一个元素给 3–5 个候选定位方式，平台改版时能自动降级
- **宁可报错也不瞎点**：找不到元素就抛异常 + 截图，绝不猜着点
- **发布前合规预检**：命中红线直接拒发，不进发布流程
- **dry-run 默认**：先走完流程不点发布，验证通过再放开
- **异常截图**：每一步异常都落盘截图，便于事后排查

## 五、自动互动

- 评论**必须来自预生成队列**（`data/engagement/comments_queue.json`），
  内容是**有信息量的真实回复**，不是"写得真好""学到了"这类水评
- 队列用尽时**只报告不足，禁止现场编造**
- 互动目标 = 同赛道关键词搜索结果，逐条浏览后按概率操作

## 六、门禁机制（前 N 篇人工检查）

```
config.APPROVAL_GATE = {"enabled": True, "first_n": 3}
放行状态存独立文件 .runtime/approved.json  ← 不污染源码
```

- 命中门禁 → 自动强制 dry-run：走完上传图片、填标题正文标签的完整流程，
  **但绝不点发布**，同时把截图与核对件写到 `review/`
- 自动化脚本**改不了**放行文件，只能由人（或人明确指令下的 Agent）执行 `approve.py --id xxx`
- 检查清单要能**不登录就检查**：标题、正文全文、标签、封面图、核对点全部落盘成文档

## 七、已知不可消除的风险（必须如实告知）

1. **平台改版会导致选择器失效** —— 脚本会报错而非瞎点，需一次联调修复
2. **自动化发帖在多数平台条款下属灰区** —— 风险可以压到很低，但不是零，这是"全自动"的固有代价
3. **第三方采集工具的使用条款** —— 例如 MediaCrawler README 明写"仅供学习参考，禁止商业用途"，
   用于自有账号选题调研属灰区，需使用者自行判断
