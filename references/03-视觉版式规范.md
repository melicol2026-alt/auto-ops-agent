# 03 视觉版式规范

## 一、为什么不用模型出图

| 模型出图 | 代码渲染 |
|---|---|
| 每次烧额度，无法每日批量 | 零额度，一天出 36 张无成本 |
| 中文常乱码、缺字 | 文字 100% 准确 |
| 每次风格不同，没有视觉识别 | 风格零差异，利于建立识别 |
| 改一个字要重新生成 | 改文案重跑即可 |

**结论**：运营类图文（大字报、清单、对比）用代码渲染，只有需要真实照片/插画时才考虑模型出图。

## 二、为什么深色大字报不行（小红书实测教训）

一套"近黑底 + 白字 + 金黄点缀"的极简排版，技术上没问题，但作为小红书封面只有 60 分，
四条硬伤：

1. **自相矛盾（最致命）**：账号主张"我查了三步、我给你过程证据"，封面里却只有一句标题，
   没有任何证据痕迹。用户凭什么信一个连痕迹都不敢露的人？这叫"主张无支撑"，比难看更致命——
   难看只是不点，主张无支撑是点了也不信。
2. **深色在浅色信息流里被识别为广告/公众号搬运**，天然有距离感。
3. **封面没有信息量可视化**：只有标题，看不出"我能得到什么"。
4. **内页纯居中大句，没有阅读节奏**，翻两页就腻，完读率撑不住。

## 三、推荐方案：浅色暖底 + 按内容类型分版式

### 配色
```
底色  #F7F3EC   奶油暖白
主文字 #1F2328  近黑
副文字 #6B7280  灰
强调  #E4572E   橘红（用于批注、数字、强调条）
分隔  #E5E0D8   浅灰线
```

### 画布
小红书 **1080 × 1440**（3:4）。其他平台：抖音 1080×1920，公众号封面 900×500。

### 三种封面版式

#### A. `evidence` 证据窗（能给证据时**优先**）
```
顶部：方向标签
中部：模拟对话框气泡（放 AI/系统给出的原文）
气泡右侧：红色批注（放打脸事实，如"法院核查：6 起全部查无此案"）
下方：横线 + 副标题（可执行承诺）
底部：来源行（小字，必须带媒体名与时间）
```
这是最能建立信任的版式——把"我查过了"直接画在封面上。

#### B. `list` 清单数字（能数条数时）
```
超大数字（如 5 / 6）+ 单位（个特征 / 类不要喂）
下方列出前 4–5 条清单预览
底部一行可执行承诺
```
用户扫一眼就知道能得到几条，点击动机最明确。

#### C. `compare` 前后对比（能前后对照时）
```
左栏「之前」：原始做法 → 结果（红色）
右栏「之后」：改进做法 → 结果（绿色）
底部可执行承诺
```

### 选用规则
能给证据 → `evidence`；能数条数 → `list`；能前后对照 → `compare`；皆可时优先 `evidence`。

### 内页版式
```
顶部：灰色小标签
中部：编号 + 短句（一页只说一句话）
底部：强调条（本篇的一句话结论）
右下角：页码
```

## 四、渲染实现要点（踩过的坑）

1. **字体缺字形**：`✗` 在微软雅黑里没有字形，会渲染成方框。改用 `×` 或用 ASCII 替代。
   实现后必须**实际打开图片检查**，不能只看代码跑通。
2. **文本超宽**：来源行、长标题容易超出画布。实现自动降字号循环：
   `while 文本宽度 > 可用宽度 and 字号 > 下限: 字号 -= 2`。
3. **中文字体路径**：Windows 用 `C:/Windows/Fonts/msyh.ttc`（常规）、`msyhbd.ttc`（加粗）。
   上线前先探测字体是否存在。
4. **每篇页数**：封面 1 张 + 内页 6–8 张，控制在 9 张以内（平台上限与完读率平衡）。
5. **路径稳定性**：重出素材时**不要改文件路径**，否则已生成的发布队列要重建。

## 五、主题切换
深浅两套主题用同一个 `theme` 参数控制，`make_pack.py --theme light|dark` 一键全套重出。
默认用浅色。
